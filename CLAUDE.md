# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Video object tracking (EfficientTAM, SAM2.1, SAM3) managed locally with uv on the Mac, but **executed on `spark2`** (DGX Spark, GB10, aarch64, CUDA 13). Nothing runs on the Mac except the browser: torch comes from the cu130 index with a linux-only marker, so there is no usable local venv (pyright reports unresolved `torch`/`numpy` imports locally; that is expected).

## Commands

```bash
# Offline benchmark: rsync to spark2:~/GWorkspace/TrackAnything, `uv run track.py` there, copy results/ back
./run_spark2.sh data/albatross.mp4 --point 470,260 --out results/birds_s.mp4             # EfficientTAM-S (default)
./run_spark2.sh data/albatross.mp4 --point 470,260 --model ti|sam3 [--runs 3] [--no-compile]
./run_spark2.sh my.mp4 --box x0,y0,x1,y1
./run_spark2.sh data/garbage_cans.mp4 --box 248,617,392,785 --out results/garbage_cans_blue.mp4   # second sample (brown: 392,624,498,761)
./run_spark2.sh data/garbage_cans.mp4 --text "garbage can . trash can" --out results/cans.mp4      # several objects / text prompt
./run_spark2.sh data/albatross.mp4 --point 470,260 --fix-box 75:1:548,172,742,315   # correct object 1 at frame 75 (also --fix F:K:x,y:+|-)
./run_spark2.sh my.mp4 --text "car . truck" --threshold 0.30 --redetect 15       # detector every 15 frames: late objects get tracks

# New sample clip without personal data (copies to spark2, always deletes the copy there; review the sheet)
./anonymize_spark2.sh my_clip.mov data/garbage_cans.mp4 --subject "garbage can . trash can"

# Live app: Mac camera -> spark2 -> browser at http://localhost:8765 (opens automatically)
./live_spark2.sh [--model sam2|sam3|etam-s|etam-ti|<hf sam2 id>]     # start model (default sam2); the page switches; NO_OPEN=1: no browser tab
pkill -f live_spark2.sh                                               # stop; also kills the server on spark2

# Second GB10 host for parallel tests (same scripts): HOST=spark3 ./run_spark2.sh ... / HOST=spark3 ./live_spark2.sh
# spark3 quirks: no python3.12-dev (venv rebuilt on uv-managed CPython: UV_PYTHON_PREFERENCE=only-managed uv sync
# --python 3.12) and a root-owned ~/.triton/cache (set TRITON_CACHE_DIR=$HOME/.cache/triton-trackanything). Never sudo.

# Tests (manual 5.6) and diagnostics
./test_spark2.sh [-k test_ws]                                         # GPU suite on spark2; TEST_MODEL=sam2, HOST=spark3
uvx pyright live.py track.py tests/
```

Tests (manual 5.6): `./test_spark2.sh` syncs to spark2 and runs `python -m unittest discover -s tests -v` there (~6 min, EfficientTAM-S); `TEST_MODEL=sam2|etam-ti|sam3`, `HOST=spark3`, `-k test_ws` (any name part) select model, host and tests. `tests/common.py` caches one tracker and the detector per process; `test_ws.py` serves `live.make_app()` in-process (aiohttp `TestServer`); `test_offline.py` runs `track.py` and `tools/anonymize.py` as subprocesses (`--with imageio-ffmpeg`). Page check on the Mac: close every tab on the live app (a second viewer drives the same shared tracker), `NO_OPEN=1 ./live_spark2.sh --model etam-s &`, then `uv run --no-project --with playwright python tests/page_check.py` (Chromium + WebKit, canvas camera; not `test_*` so the hosts skip it). Regression value: `./run_spark2.sh data/albatross.mp4 --point 470,260` prints `frame0` ≈ `3.03%` (3.022–3.038 between runs: the compiled encoder is not deterministic) for EfficientTAM-S (about 100 FPS); `test_offline` checks it.

## Architecture

- `track.py`: offline CLI; it also defines `load_efficienttam(size)`, which `live.py` and `tools/anonymize.py` (through `live.load`) use. It decodes the video to a JPEG folder (the upstream predictor's only input), prompts frame 0 with one object per `--point`/`--box` and per `--text` detector box, and times `propagate_in_video`. The union `mask area:` line keeps its old format (regression check); with several objects it adds one line per object. Objects 1–8 use the page palette, later ones `colour(k)` golden-ratio hues (no limit on objects). `--fix`/`--fix-box` (EfficientTAM only, manual 5.7): `track()` propagates once, `correct()` turns each fixed frame into an init-conditioning frame with `live.as_cond_frame` (shared with `Prompted.fix`: negatives-only get `anchor()` or are skipped on an empty mask, f is popped from `frames_tracked_per_obj`, the object's non-cond outputs before f go: old memory out-voted the box, IoU 0.01; points keep f's old logits as dense prompt, a box pops frame f's outputs so the old mask cannot override it), then propagates again from the first fixed frame and merges into the first pass. Points on a different object move the track there (SAM picks one object); `tests/test_fix.py` checks this. `--redetect N` (EfficientTAM only, manual 5.8): `track_redetect()` streams through `live.load()`'s tracker (not the JPEG-folder path), with `add_boxes(found, True)` every N frames (it drops boxes with IoU ≥ `DUP_IOU` against a mask's box). The new object's first mask then decides the other duplicates (`on_old`, `SAME`, ignoring masks that are `TOO_BIG`); do not reject a box because it contains a mask (the girl's box holds the boy's mask: she got no track). Tracks end after `LOST` empty frames or at `TOO_BIG` of the frame (a sports field), `MAX_OBJECTS` 64 replaces `live.MAX_OBJ`. Offline only: in live the detector would stall the frame loop. `tests/test_redetect.py`.
- `detector.py`: `Detector` (LLMDet tiny, thresholds as arguments) and `split_names`, shared by `live.py`, `track.py` and `tools/anonymize.py` so the offline tools need not import the server.
- `tools/anonymize.py` + `anonymize_spark2.sh`: personal-data removal for sample clips (manual 5.5). The hosts have no ffmpeg; the tool uses `imageio-ffmpeg` (`uv run --with`, not a project dependency). It prints `pixelated N boxes`; `test_offline` asserts N > 0, so a broken privacy step fails the test.
- `live.py`: aiohttp server bound to **127.0.0.1 only** (reached through `ssh -L`; browsers allow `getUserMedia` only on localhost/https). `ws_handler` refuses a browser `Origin` other than localhost/127.0.0.1 (HTTP 403: browsers let any site open a WebSocket to localhost; no Origin = scripts/tests, allowed), and clears the active track when a viewer connects. Text messages pass `valid()` (types at the trust boundary) or get `{"message_error": "bad message: ..."}` (its own key: it is not a frame reply, so the page must not send the next frame on it); a frame that fails in the tracker (not `BadFrame`, a decode failure) clears the track and replies `tracking failed, track cleared` instead of ending the connection. One shared tracker, one viewer (`ws_handler` closes a second connection with `BUSY` = 4001; the page shows "Busy · retrying" and retries every 2 s), one frame in flight.
  - Per frame: browser JPEG → `decode()` (nvJPEG, `torchvision.io.decode_jpeg(device="cuda")`) → `tracker.step(rgb)` returns **low-res mask logits** → `pack()` → JSON `{ms, areas: [per object], labels: [per object], ids: [per object], w, h}` then one binary message of raw **float16** logits, N grids of h × w in object order (128² EfficientTAM, 256² SAM2, 288² SAM3). `{"areas": []}` with no binary message means no prompt. Text messages from the page: `{"x","y"}` or `{"box":[...]}` (0..1 normalized) start a new track, the same with `"obj": "new"` adds an object (max `MAX_OBJ=8` at a time; ids are stable numbers assigned in order and never reused, so after removing 2 from [1, 2, 3] they are [1, 3]; `ids` in each reply gives the id of each grid), `{"x","y","add":1|0,"obj":k}` is a correction point on object k, `{"remove": k}` drops object k, `{"text": "boy . cup"[, "obj": "new"]}` is a text query (string ≤ 200 chars, split on `.,;`), `{}` clears, `{"model": id}` switches. The reply of the frame a query ran on adds `found: [{label, score}]`; a bad query or detector load failure replies `{"find_error": ...}`. On connect the server sends `{"models": [...], "model": active}`. `switch()` accepts only ids in `MODELS` (the page must not trigger arbitrary HF downloads), loads on first use in a worker thread, caches every loaded tracker in `app["state"]`, and replies `{"model": active[, "error"]}`. `app["state"]` is a mutable dict because aiohttp freezes app keys after startup.
  - `Tracker` wraps the HF transformers streaming video API (`Sam2Video*`, `Sam3TrackerVideo*`). `EfficientTAMTracker` fakes streaming on the upstream offline predictor. It seeds `init_state` with a one-JPEG temp dir (re-encoded from the decoded frame, because PIL rejects truncated input), replaces `state["images"]` with a dict, sets `num_frames = t+1`, and calls `propagate_in_video(start_frame_idx=t, max_frame_num_to_track=0)`. It reads the low-res `pred_masks` from the output dict. Both trackers call `prune()` to drop history older than `KEEP=16` frames, so memory stays flat.
- `live.html`: a visible `<video>` (the camera preview must never depend on the backend), a WebGL2 `#mask` canvas and a 2D `#overlay` canvas for clicks and the drag box. The shader uploads the logits as an `R16F` texture, upsamples bilinearly, thresholds at `> 0` and colours. This matches the server-side `F.interpolate(..., align_corners=False) > 0` exactly. Do not quantize to uint8: clamping moved edges (IoU 0.91). The page sends the next frame as soon as the JSON reply arrives.
- `live_spark2.sh` / `run_spark2.sh`: rsync then ssh. `HF_TOKEN` (needed for gated `facebook/sam3`) goes to spark2 over **stdin, never argv**. In the live launcher, the stdin pipe also works as a lifeline: when ssh dies, the remote `cat` hits EOF and kills `live.py`, and the trap kills ssh on Ctrl-C/pkill.

- Correction points (`Prompted.fix`): pending points go on the last tracked frame `t-1`, which is re-run as a new conditioning frame (removed from `frames_tracked_per_obj`, so no memory attention) with its current logits as the dense prompt, then non-cond memory up to `t-1` is dropped. On a tracked frame the memory ignores the clicks, and old memories out-vote the fix within frames. HF `forward()` cannot pass the logits, so `Tracker._fix` injects `prev_sam_mask_logits` by wrapping `_run_single_frame_inference` for that one call; `Tracker.__init__` asserts the private signature, so a transformers upgrade that changes it fails at load. Negative-only fixes get an `anchor()` positive point (SAM empties the mask otherwise). Tests: `tests/test_tracker.py`, on `data/albatross.mp4`. SAM picks one bird, so a mask with two areas does not occur there: remove points cut part of a bird (40% stays on EfficientTAM-S, 64% on Ti, 6% on SAM2.1), and add points on the other bird move the track on EfficientTAM-S and are ignored on Ti and SAM2.1 (skipped there).

- Object ids (`Prompted.ids`, `next_id`): stable for the whole track (the page gives each new id the lowest free of 8 palette slots and keeps it until the object goes away), never reused; `ids` is in upstream order (session objects first, then pending), so upstream index = position. Upstream object ids are our ids. `remove(k)` queues `removals`; the worker's `apply_removals(self._drop)` deletes the object (pending: from `pending`; in session: `drop_index()` re-keys the per-object dicts and each tracker rebuilds its id maps). EfficientTAM's own `remove_object()` is not used: it re-runs the object's prompt frames, whose images `prune()` freed. HF has no removal API. Removing the last object resets the track.
- Multi-object (`Prompted.pending`/`add_object`/`take_new`): a new object is added on the next frame (`frame_idx = t`), which becomes its prompt frame; others keep tracking. HF `add_inputs_to_inference_session` *replaces* `session.obj_with_new_inputs` on every call, so `Tracker.step` resets it to all objects added this frame (else same-frame objects crash with "maskmem_features ... cannot be empty"). `Tracker._fix` re-runs frame f for all objects; the `prev_sam_mask_logits` injection applies only to `obj_idx == i`. Cost per added object is roughly a full memory-attention + decoder pass (manual 10.3).
- Text prompts (`Detector`, `parse_query`, `step()`): detect once, then track. The handler only stores `state["query"]`; the worker `step()` runs `Detector.find()` on the decoded frame, then `Prompted.add_boxes()` turns the boxes into objects (`set_prompt` for the first box in New mode, else `add_object`) before `tracker.step`. Each object keeps its detector label in `Prompted.labels`; every reply carries `labels` next to `areas`, so the page holds no label state. `DETECTOR` is a fixed id (LLMDet tiny, chosen by the bake-off in manual 10.4; no `timm`), loaded lazily on the first query and kept in `app["state"]["detector"]`. Thresholds: box 0.35 (0.30 let a 0.31 "giraffe" through), text 0.25, NMS 0.7 across labels; in Object mode `add_boxes` drops boxes with IoU ≥ `DUP_IOU` 0.5 against `mask_boxes(self.last)` (each tracker's `step` stores `self.last`) (the girl came back as "boy" at 0.55 > the real boy's 0.40). Nothing found leaves the current track as it was. Query lifecycle: the handler moves the query into the next binary frame and clears it first (it runs on one frame even if that frame fails); a model switch, prompt or clear cancels a query that has not run (corrections do not); a detector exception becomes `found: []` + `find_error` in that frame's reply. The page allows one search at a time and tags it with an `id`; replies echo `find_id`, and the page ignores a reply whose id is not its current search. `Detector.find` has no count limit: `add_boxes` drops boxes on tracked objects before filling free slots.

## Gotchas

- `pyproject.toml` pins EfficientTAM to git rev `abcd061` and overrides its bloated requirements via `[[tool.uv.dependency-metadata]]`. The wheel omits its Hydra YAMLs, so `configs/` holds copies of the 512×512 configs, loaded via `GlobalHydra.clear()` + `initialize_config_dir`. Refresh `configs/` when bumping the rev.
- `torch.compile` works for EfficientTAM's image encoder (warmed up at server start), but fails for the HF SAM2 encoder on spark2's Triton (`KeyError: triton.language.bfloat16`).
- autocast is thread-local, so `EfficientTAMTracker.step` enters it itself (it runs inside `asyncio.to_thread`).
- The upstream CUDA extension `_C` is not built, so hole-filling is skipped with a warning. That is expected.
- Mac port 8000 is taken by another process, so the live port is 8765.
- `data/` holds only clips without personal data. Make new ones with `anonymize_spark2.sh` (metadata and audio stripped, everything outside the tracked subject blurred, plates/house numbers/faces on it pixelated), then check the sheet and the video (manual 5.5). Never commit the original. The launcher keeps it out of the rsync, uploads it to a `mktemp -d` (0700) dir, the host deletes it when the tool exits (trap on EXIT/HUP/INT/TERM), the launcher removes the dir, and a 6 h host-side timer is the backstop. The tool streams (two reads of the clip; packed low-res masks only), and boxes borrowed from neighbouring frames move with the object's centroid and do not count as coverage. `--max-area` drops only large boxes whose label contains "number" (whole bins); every other PII label is pixelated at any size.
- No YOLO / Ultralytics anywhere (AGPL-3.0, no Ultralytics licence); same for Segment-and-Track-Anything code. Prefer Apache/MIT detectors and trackers. YOLO26 was run once in the scratchpad for the manual 10.5 comparison only.
